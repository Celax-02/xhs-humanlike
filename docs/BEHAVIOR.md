# 行为模型详解

这一页解释 `xhs_auto.py` 里每个随机数**为什么这么随机**，以及想调整时该动哪一行。

如果只想知道怎么跑，看 [README](../README.md) 就够了。

---

## 设计原则：随机的形状比随机的范围重要

初版脚本是这么写的：每屏 `if random() < 0.55: 点开`，每篇停 `uniform(6, 16)` 秒，每篇往下翻 `randint(2, 9)` 次评论。

问题是这些数字看起来随机，**分布形状却是错的**：

| 环节 | 初版 | 真人实际 |
|---|---|---|
| 停留时长 | 均匀分布，6~16 秒各占 1/11 | 重尾：多数 3~8 秒，少数 40 秒以上 |
| 评论深度 | 均匀分布，2~9 次各占 1/8 | 大量 0 次（看一眼就退），少量 15+ 次 |
| 滑几屏才点开 | 每屏独立掷骰 | 有节奏：连着划几屏才点一个 |

均匀分布的直觉是"每个值机会均等"，但人的行为从来不是均等的 —— 它总是**大多数很快、极少数极慢**，也就是重尾分布。

所以整个模型换了分布族：

| 用什么 | 替代了什么 | 为什么 |
|---|---|---|
| 对数正态 `lognorm()` | 停留时长 | 人的阅读/观看时长几乎总是对数正态，这是行为科学里的经典结论 |
| 指数分布 `expovariate()` | 评论深度 | 每多看一条评论，继续看的概率近似恒定 → 几何/指数衰减 → 长尾 |
| 几何分布 `geom()` | 滑屏配额 | 同上，"再划一屏就点"的概率恒定 |
| 随机游走 | 每段独立抽签 | 行为有惯性，不能每段重新掷骰 |

## 五个随机层

### 1. 触摸轨迹层：手指不是鼠标

`input swipe` 的底层实现是**直线 + 匀速**，两点之间线性插值，速度恒定。真人的手指不会这样：

- 走不了绝对直线，会有几像素的横向漂移
- 速度是加速—匀速—减速，不是恒定
- 甩一下和慢慢拖，速度曲线完全不同

`drag()` 用 `input motionevent` 分段注入，三个参数各管一件事：

```python
def drag(x1, y1, x2, y2, dur_ms, bow=None, ease="smooth", steps=None)
```

| 参数 | 作用 | 实际取值 |
|---|---|---|
| `bow` | 横向弓形偏移（px），路径变成 `x + bow·sin(π·t)` | 50% 为 0（几乎笔直），其余 3~24px 随机方向 |
| `ease` | 时间→位移的映射，决定速度曲线 | `smooth` 慢起快中慢收 / `out` 快起减速（甩）/ `in` 慢起加速（拖重物） |
| `steps` | 分段数，由单条 `input` 命令的真机耗时反推（实测约 90ms/条），4~22 段 | 每段一个 MOVE 事件，段间带 ±1.3px 的纵向噪声 |

### 长按误触：为什么起步必须「一动就走」

这是这个项目踩过最深的一个坑。`input motionevent` 每发一条都要在设备上起一个进程，实测 **90~110ms**。如果按「27ms 一段」估步数，一条本该 1.2 秒的慢拖会在屏幕上按住 2 秒多；再叠上 `smooth` / `in` 这类慢起曲线，前几百毫秒位移还不到 10px。

安卓的长按判定是：**按住超过 500ms，且位移没超出触摸容差（约 16px）**。于是：

- 在信息流里 → 卡片被长按，弹出「不感兴趣 / 分享」
- 在详情页里 → 图片被长按，弹出「保存图片 / 分享到…」

这不是「点错了」，而是手势时间轴本身失真。两个修正：

1. **步数按真机开销算**：`per = max(50, STEP_COST_MS + 16)`，`steps = dur/per`，让屏上停留时间接近 `dur_ms`。真机开销在启动时用 `input keyevent 0` 实测（`measure_input_cost()`），不写死。
2. **给曲线垫一个初位移**：`e = start + (1-start)·ease(t)`，其中 `start = min(0.35, max(0.05, 26/dist))`。第一个 MOVE 就会走 26px 以上，按 90ms 落地 —— 长按计时器在 90ms 就被取消，而整体曲线形状不变。

另外加了一道兜底：`is_share_sheet()` 靠节点里的「保存图片 / 不感兴趣 / 复制链接」等固定文案认出这个浮层（它在同一个 Activity 里，`focus()` 看不出来），`dismiss_share_sheet()` 按一次返回关掉。评论区每划 3 下抽查一次。


### 2. 滑动力度层：四种手势

信息流里的上滑不是一种动作，`feed_swipe()` 按权重抽四种：

| 类型 | 权重 | 行程 | 手指时长 | 效果 |
|---|---|---|---|---|
| `flick` 甩 | 30% | 550~900px | 105~185ms | 一屏多一点，带惯性 |
| `normal` 翻页 | 60% | 420~780px | 190~460ms | 正好一屏 |
| `half` 半途 | 10% | 180~420px | 200~400ms | **不够翻页，页面回弹** |
| `tiny` 手抖 | 6% | 18~60px | 120~220ms | 几乎没动 |

`half` 和 `tiny` 是关键。真人划手机经常会有"试了一下但没划过去"的动作，纯自动化不会有，而这恰好是行为特征里很容易被区分的一类。

### 3. 停留时长层：对数正态 + 三个修正

```python
v = lognorm(base, sigma, lo, hi)      # 基础：对数正态
v *= 0.70 + energy * 0.62             # 精力修正
v *= 0.62 + depth * 1.15              # 深度修正：有料的看得久
if imgs >= 6: v *= uniform(1.08, 1.35)  # 内容量修正
if chance(0.06): v *= uniform(1.6, 2.6) # 6% 被彻底吸住
```

四种风格的参数：

| 风格 | 中位数 | sigma | 硬上下限 |
|---|---|---|---|
| `glance` 扫一眼 | 2.4s | 0.42 | 1.2 ~ 8s |
| `image` 看图 | 4.2s | 0.50 | 2.0 ~ 26s |
| `read` 阅读 | 9.5s | 0.52 | 3.5 ~ 62s |
| `comments` 看评论 | 6.5s | 0.48 | 2.5 ~ 34s |

`sigma` 控制尾巴有多重：0.42 表示"基本都在中位数附近"，0.52 表示"经常冒出很长的停留"。想让它更有耐心，优先加 `sigma` 而不是加 `base` —— 加中位数会变成"每篇都停很久"，加 sigma 才是"偶尔停很久"。

> 日志里打印的 `停 Ns` 是**实际在帖子里的总时长**，包含翻图和翻评论，所以会比上面的中位数大。

### 4. 评论区层：指数分布 + 耐心衰减

```python
r = random.random()
if r < 0.22: return 0                      # 打开看一眼就退
if r < 0.40: return randint(1, 3)           # 浅翻
n = 3 + int(expovariate(0.30 / energy))     # 长尾，上限 24
```

22% 完全不翻是最重要的一档。真人点开帖子，多数时候根本不看评论。

下滑过程本身也在变：

- 前 1~3 次用 `power 1.15~1.6` 快速甩，把评论区拉出来
- 之后用 `lognorm(0.72)`，多数是慢拖（手指 900~1600ms），偶尔用力
- 每往下一步，停留时间按 `fade` 线性衰减最多 35%（耐心递减）
- 14% 概率划过头了往回拉一点
- 5% 概率停在某处多看 5 秒

### 5. 会话层：精力（energy）

这是唯一一个**跨段共享**的状态。每段结束时：

```python
energy += random.gauss(0, 0.17) - frac * 0.045   # 随机游走 + 随时间轻微衰减
energy = clamp(energy, 0.05, 0.95)
```

它同时影响四个地方：

| 影响点 | 公式 | 效果 |
|---|---|---|
| 阶段权重 | `skim: 0.30·(1.65-energy)`，`deep: 0.18·(0.35+1.5energy)` | 精力低更容易抽到"快速划过" |
| 停留时长 | `× (0.70 + 0.62·energy)` | 精力低看得快 |
| 评论深度 | 指数分布的 λ 除以 energy | 精力低翻得浅 |
| 阅读/看评论风格权重 | `× (0.55 + energy)` | 精力低更倾向扫一眼 |

作用是**制造惯性**。没有它，每个随机数互相独立，行为序列看起来像白噪声；有了它，一段沉迷之后更容易接着沉迷，一段浮躁之后也更容易继续浮躁 —— 这才是真人刷手机的样子。

日志里的 `(精力 0.54)` 就是它，调试时可以观察它有没有合理地漂移。

## 内容感知：按标题决定注意力

真人对不同标题的注意力完全不同，`pick_style()` 会先做一次文本判断：

| 标题特征 | 权重变化 | 依据 |
|---|---|---|
| 含 `？?` | 看评论 ×2.5，扫一眼 ×0.6 | 人看到问句会去评论区找答案 |
| 含 `攻略/教程/干货/保姆级` | 阅读 ×1.9，看评论 ×1.2，扫一眼 ×0.45 | 工具型内容值得细读 |
| 含 `求助/翻车/踩坑/报错` | 看评论 ×1.9 | 这类帖子的价值在评论区 |
| 长度 ≤ 8 字 | 扫一眼 ×1.8 | 信息量少，划走快 |
| 长度 ≥ 24 字 | 阅读 ×1.35 | 长标题通常是有信息量的分享 |

加这一层的原因是：纯随机选择风格会让日志出现"扫一眼"一篇 9 图长文、"翻评论"一篇只有标题的帖子这种别扭组合。加了文本判断之后，行为序列在语义上也说得通。

## 深度分级：梗图扫两眼就走

`--depth` 开启后，每篇帖子先算一个 0~1 的深度分 `depth_score(title, imgs)`，再分成三档。评分只用标题和图片数，不做真正的语义理解——但人挑帖子本来也就看这两样。

**加分项**：方法论/原理/复盘类词（`为什么`、`原理`、`拆解`、`复盘`、`架构`、`实测`、`踩坑`…，每个 +0.16，上限 +0.42）；中性信息词（`观点`、`行业`、`产品`、`团队`、`决策`…，每个 +0.055，上限 +0.15）；长标题（≥22 字 +0.12）；问号（+0.07）。

**减分项**：梗图类词（`meme`、`梗`、`表情包`、`笑死`、`壁纸`、`九宫格`…，每个 −0.34，上限 −0.62）；广告类词（`报价`、`限时`、`招生`、`加盟`、`到手价`…，每个 −0.26，上限 −0.50）；短标题（≤8 字 −0.16）；emoji 数量（每个 −0.045）；9 图以上且标题很短（−0.12，多半是图集）。

三档对应三种行为：

| 档位 | 分数 | 选卡权重 | 行为 |
|---|---|---|---|
| 有料 `deep` | ≥ 0.60 | `1 + pref·(d−0.45)·2.6`，最高约 2.1 | 阅读 ×2.3、看评论 ×1.7、扫一眼 ×0.30；评论区额外多翻 2~7 次；收藏概率按 `deep_boost^1.7` 加成 |
| 一般 `normal` | 0.32~0.60 | ≈1.0 | 与原来一致 |
| 没料 `shallow` | ≤ 0.32 | 最低 0.06 | 翻 1~2 张图、停 2~3 秒、不点赞不翻评论直接退 |

几处细节：

- **梗图不是屏蔽，是低概率**。选卡权重的下限是 0.06 而不是 0，真人也会手滑点开。点开之后还有 `0.45 + 0.5·pref` 的概率走"秒退"分支——「点开秒退」本身就是给推荐系统的负反馈。
- **深度偏好会改行为配比**：快划段权重 ×`(1−0.30·pref)`，沉浸段 ×`(1+0.90·pref)`。养号阶段看长文比刷屏有用。
- **收藏比点赞更挑**。点赞门槛低，收藏的本质是「以后还要回来看」，所以深度加成给在收藏上，指数 1.7 比点赞的线性更陡。

日志里有料标 📚、没料标 💤，收工时单独统计各档占比与深帖平均停留。

## 行为段：四种注意力状态

整场不是"一个动作接一个动作"，而是分成行为段，每段连续做一串同类动作：

| 段 | 权重（随精力浮动） | 做什么 | 长度 |
|---|---|---|---|
| `skim` 快速划过 | `0.30·(1.65-energy)·(1−0.3·depth)` | 连续快划，什么也不点 | `lognorm(8)` 屏，3~26 |
| `drift` 正常浏览 | 0.45 | 滑几屏点一篇，再滑几屏 | `lognorm(95)` 秒（35~210）或点开 `lognorm(4)` 篇（2~10），先到为准 |
| `deep` 沉浸细看 | `0.18·(0.35+1.5energy)·(1+0.9·depth)` | 连着点开好几篇，中间不回信息流 | `lognorm(3)` 篇，2~6 |
| `rest` 休息 | `0.02+0.07·(1.7-energy)` | 停下滑动 | 70% 是 12~150s，30% 是 2.5~30s |
| `topic` 定向浏览 | 仅 `--topic`，`0.10+1.6·缺口` | 搜主题词 → 翻结果 → 点开 → 回信息流 | 2~8 篇 |

相邻两段不会重复（`last` 变量排除），避免出现"连着三段都在快划"。

`topic` 段是唯一按"目标达成度"动态加权的段：缺口 = `目标比例×(已点开+1) − 已命中`，缺口越大权重越高。所以它不会平均分布，而是在占比落后时集中补几次。

`drift` 段里的**配额机制**值得单独说：

```python
quota = geom(0.42, 0, 9) if chance(0.85) else randint(10, 18)
```

滑够 `quota` 屏才点开一篇，而不是每屏掷骰子。这样能产生"连着划 5 屏才点一个"的节奏，甚至有 15% 概率是 10~18 屏的长划。用每屏掷骰子的话，数学上等价于"平均 1.8 屏就点一次"，节奏会机械得多。

**每一段都必须自己收尾。** `drift` 是权重最高的段，早期版本里它的循环条件写成了 `while time.time() < deadline`（全局 20 分钟截止时间），结果一抽中就把整场吃满：主循环再没机会重抽状态、重算精力，整场日志只有一行 `▸ 正常浏览`，搜索段也永远排不上，主题命中率因此上不去。现在由 `drift_budget()` 给出时长和篇数双上限：

```python
span, budget = drift_budget()          # 35~210 秒、2~10 篇
seg_end = min(deadline, time.time() + span)
while time.time() < seg_end and opened < budget:
    ...
```

其余四段本来就有上界（屏数、篇数或固定时长），不存在这个问题。`tests/test_phases.py` 用虚拟时钟锁住了这条约束，防止改代码时再退化回去。

## 主题定向：怎么把推荐方向掰过来

默认是纯随机挑卡，刷什么全看推荐。开 `--topic ai` 之后多四层控制。默认目标 70%——不是"只刷 AI"，而是"绝大部分是 AI / AI 办公，留一点随机打散"。

**一、选帖按配额纠偏**

```python
need = ratio * (已点开 + 1) - 已命中
p = clamp(need + gauss(0, 0.22), 0, 1)
```

不是固定概率抛硬币，而是按"当前缺口"决定这一篇该不该挑相关内容。占比落后时几乎必挑，跟上后又回落。加 `gauss` 噪声是为了不出现严格交替（AI、非 AI、AI、非 AI 那种一眼假的节奏）。

**二、方向明显不对的压下去**（`--topic-strict`，默认 0.6）

```python
topic_bias = 1 + 1.8*strict        # 命中主题
           = max(0.04, 0.35-0.30*strict)  # 跑偏词：月子中心/留学中介/探店/车展
           = max(0.15, 1-0.60*strict)     # 普通非主题
```

乘在深度权重上。真人偶尔也会手滑点开一条本地生活，所以不是硬屏蔽；但连续好几轮都点这些内容，等于在给算法喂反向信号。

**三、信息流里找不到就找一下**

屏幕上没有相关内容时，不会随手挑一张凑数：先划 1~3 屏再判断，最多 3 次。快划（`skim`）途中如果扫到相关标题，有 13% 概率停下来点开——真人刷信息流被某条拽住就是这个动作。

**四、内容不够就去搜**

实测信息流里 AI 类内容只占约 9%，光靠挑凑不到七成。所以模型里加了 `topic` 段：搜一个主题词、翻结果页、点开、回信息流。越偏离目标比例，进这个段的权重越高。

`adb input text` 打不出汉字，但小红书支持 `xhsdiscover://search/result?keyword=<urlencoded>` 直达搜索页，所以 `AI办公`、`AI会议纪要`、`AI写PPT` 这类中文词可以直接用；scheme 不可用时自动降级成 ASCII 词。**启动必须带 `--user <uid>`**：应用分身（`u999`）不带的话会拉起主用户 `u0` 的实例，养到另一个账号上。uid 从 `mCurrentFocus` 里读。

搜索结果页和推荐流的界面结构完全不同（双列瀑布流、卡片没有 `content-desc`），所以单独写了一个解析器：靠"可点击的大块矩形 + 落进矩形内的文字节点"定位卡片，并把带「广告」标记的跳过。

**五、命中之后的行为**

| 项 | 变化 |
|---|---|
| 停留时长 | ×1.12~1.45 |
| 点赞概率 | ×1.9（上限 30%） |
| 收藏概率 | ×1.6（上限 20%） |
| 阅读 / 看评论权重 | ×1.45 / ×1.25 |
| 扫一眼权重 | ×0.55 |

这些是"用行为表达兴趣"的部分。只挑不互动，推荐系统收到的信号很弱。

## 微动作清单

这些是让日志看起来"有人在"的细节，每一条都对应一个真实场景：

| 动作 | 概率 | 实现 |
|---|---|---|
| 点错了立刻退回 | 9% | 停 0.4~2.6s 就按返回 |

| 回看上一张图 | 12%（第 2 张之后） | 反向横滑 |
| 刷的过程中往回翻 | 5~8% | `feed_swipe_back()` |
| 看完一篇缓一下 | 30% | 在信息流停 0.5~12s 不动 |

## 想调参数？对照这张表

| 你的感受 | 改哪里 | 怎么改 |
|---|---|---|
| 刷得太快，不像在认真看 | `dwell_time()` 的 `base` | 三个值一起 ×1.3，先加中位数 |
| 偶尔该有一篇停留很久 | `dwell_time()` 的 `sigma` | 0.5 → 0.65 |
| 点开得太频繁 | `seg_drift()` 的 `quota` | `geom(0.42)` 的 0.42 降到 0.28 |
| 评论翻得太深 | `comment_depth()` | `0.22` 提到 0.35（更多 0 次），或指数 λ 调大 |
| 整体太机械 | `main()` 里的 `0.17` | 提到 0.25，精力漂移更剧烈 |
| 一直在快划 | 同上 | 说到底是 energy 长期偏低，检查 `frac * 0.045` 衰减项 |
| 点赞太多 | `--like` | 降到 0.015 以下 |
| 想要完全可复现 | `--seed 42` | 同种子 + 同设备 = 同一场行为 |

改完至少跑 20 分钟再看效果。10 分钟的样本量不足以判断分布 —— 单篇停留的方差本来就很大。

## 一个诚实的说明

这套模型能让行为序列在**统计形状**上接近真人，但它并不是真人在用手机：

- 真人的注意力受内容驱动，这里只是关键词匹配
- 真人会因为一条评论改变整场行为，这里没有这种长程依赖
- 真人刷手机有明确目的（找东西/杀时间），这里没有目的

所以它更适合"我把手机放着让它替我翻一会儿"这种场景，而不是伪装成某个具体的人。任何声称能完全绕过风控的方案都是夸大的 —— 平台的风控维度远不止手势时序。
